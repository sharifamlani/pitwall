## Concerns (not graded)

1. **Slow starts on `18580d8`, whose startup code is the same as release.** The release walk recorded 4 starts over 1 s: 1.245 s (window9, 23:33:16), 2.205 s (window10, 23:34:26), **12.358 s** (window15, 00:10:51, a W12 reopen) and 1.108 s (window17, 00:14:46). No gate was sampled for them, so under the amended rule they are neither excused nor in the graded sample. The r3 load log 45 minutes later shows the machine at 57–99 % CPU with 0.27–1.9 GB free. The graded r4 sample is clean, but real-world first renders on a loaded machine can be seconds.
2. **E16 handoff start.** On release code, the 3 handoff cold starts had 1 other Pitwall window, not ≥ 3. The handoff start that meets the window count is on `18580d8`.
3. **E6 existing-window trials** were not re-run after #55. I graded them through the code equivalence (`Worktree | undefined` makes `||` and `??` the same).
4. **E8 first-visit focus loss is real and user-visible.** The first time after launch that Ctrl+↓ lands on a restored panel chat, focus leaves the list. That happened in 6 of 6 cases on release code. Excluded by Sharif's amendment; it belongs in the v0.5.1 known issues and the release notes.
5. **The W6 harness misreads duplicate titles.** It scores by row label, so rows with the same title score as a FAIL (r3 term-notopen printed 1/3, but was 3/3 by the log). Score by session id, or by the `route` line, instead.
6. **The guard evidence is a log line, not a capture.** Before the post names the guard, a one-time screenshot of the warning plus a process count would make line (b) self-evident.
7. **Round-1 concerns that still apply:** `dump-tabs.mjs` lists dumps of reused pids; E5's dump can't show terminal-surface chats; tabs with a default or shared title stay unmarked by design; the developer tab dump is not covered by `--check-privacy`.
